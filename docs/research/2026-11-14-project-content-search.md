# 项目文件名与内容搜索

## 调研

- [VS Code Basic editing](https://code.visualstudio.com/docs/editing/codebasics#_search-across-files) 区分文件定位与跨文件内容查找。内容结果按文件分组，提供命中数、行片段与点击定位；大小写、正则和包含/排除模式属于附加选项。
- [VS Code Search Issues](https://github.com/microsoft/vscode/wiki/Search-Issues) 说明磁盘搜索由 ripgrep 执行，打开的编辑器另行搜索；忽略规则与编码经常导致结果缺失，需要让范围和限制可见。
- [IntelliJ IDEA Find in Files](https://www.jetbrains.com/help/idea/finding-and-replacing-text-in-project.html) 将全文查找作为独立任务，展示命中文件与预览，并通过范围、大小写及文件掩码缩小搜索。

Pello 沿用既有文件、变更和搜索三个图标入口。文件名搜索属于文件标签页，内容搜索由搜索图标单独进入，不提供“文件名 / 内容”文字切换。选项顺序参考 [VS Code FindInput](https://raw.githubusercontent.com/microsoft/vscode/main/src/vs/base/browser/ui/findinput/findInput.ts) 的大小写、全字和正则排列。

## 最终交互

- 文件页在文件列表上方常驻名称搜索框，不显示占位文字，继续匹配相对路径；清空后恢复文件树浏览位置。
- 搜索图标进入内容搜索视图，重复点击聚焦输入框。名称与内容分别按项目保留查询词，内容选项也按项目保留；离开设置或切换项目后恢复。
- 内容输入框内右侧并排显示区分大小写、全字匹配、正则三个图标，单行排列，共享输入边框；220px 面板及界面字号 16 保留至少 64px 输入宽度。支持单独及组合切换，提供选中状态、悬停提示和键盘焦点。
- Ctrl+E 打开文件页并聚焦名称框，Ctrl+Shift+F 打开内容搜索，面板收起时自动展开。支持从编辑器和终端触发，不发送控制字节、不重建终端；跳过设置、模态窗口和输入法组合。快捷键同步列入设置。
- 文件名输入框约 24px 高，含留白的搜索行与文件树条目一样约 30px；内容输入框保留约 28px 高。输入和匹配片段使用正常界面字体、字号与字重，高亮仅使用背景，不加粗或放大。内容结果按文件折叠分组，仅显示文件名和高亮片段；不展示跳过统计、文件分布、行号或文件内命中数，总结果数保留在状态行。窄容器优先保留命中文字，两侧上下文可省略，完整位置可悬停查看。
- 点击结果保留列表，复用对应文件标签。由于行列对应源文件，Markdown/HTML 命中在源码视图定位；用当前文件草稿定位最近的实际匹配，保留草稿和撤销，不隐式保存。若当前草稿已无该内容，显示结果变化提示。
- 输入防抖 250ms，结果分批追加；支持停止和重新搜索。新词、选项变化、视图切换、项目切换或卸载结果区域均取消旧任务。Enter 从输入框移到第一条命中；文件名框 Esc 清空查询并返回文件树，内容框 Esc 返回搜索图标，两种输入框均不隐藏。

## 扫描和限制

磁盘内容通过主进程读取。本机采用异步、有界文件读取和拉取式批次；SSH 复用现有认证及主机指纹策略，通过 Python/PowerShell 在远端扫描，查询与规则通过 stdin 传递，只传回 JSONL 命中片段。这样不依赖用户安装 rg，也避免逐文件建立 SSH 连接。Linux 目标需要现有远程文件操作使用的 Python 3。

搜索沿用项目忽略目录配置，始终跳过点目录与链接，不新增对 .gitignore 的解释。二进制、非 UTF-8 以及超过内置编辑器 2 MB 上限的文件在后台跳过，不展示跳过统计；文件/目录读取失败单独计数。最多返回 2000 个匹配，并明确提示缩小查询。当前只搜索已落盘内容；未增加跨文件替换及文件包含掩码。全字边界包括 Unicode 字母、数字与下划线。按行匹配，CRLF 的行末锚点与 LF 一致。

正则单独校验原始表达式，再添加全字边界，避免边界包装意外修复无效表达式。本机正则在独立、可终止 Worker 内执行，每文件限制 500ms，语法错误及超时明确提示；Linux 使用定时信号，Windows 使用 .NET Regex 超时。正则字符串只作为数据传入，不插入代码。不同引擎特有语法仍可能返回不支持的表达式错误。

## 验证范围

`scripts/content-search-check.mjs` 覆盖真实主进程 IPC、20 层目录、BOM/CRLF、中文与表情字符后的 UTF-16 列号、字面量符号、大小写/全字/正则及组合、无效表达式、CRLF 锚点、正则超时、忽略规则修改、外部目录链接、二进制/编码/大小跳过、2000 上限、取消与项目隔离。Windows 使用本地 SSH 服务实际执行远端脚本；Linux 使用 WSL 实际执行 Python 扫描，并比对完整结果。

UI 用例验证文件页常驻空白名称输入、独立内容视图、独立查询、三个框内图标、精简结果、紧凑输入框高度、搜索/片段/匹配与正常字体的实际样式一致、快捷键与设置列表、停止/重新搜索、过期词取消、精确行列、命中文字在视口内、文件标签复用、Markdown 源码定位、草稿与撤销。通过实际设置切换中英文、深浅主题和界面字号 12/16，覆盖 1024×680、1440×900、约 220/420px 面板；原生 Chromium DPI 覆盖 100%/125%/150%/200%。本次截图写入忽略目录 `output/playwright/content-search/`，不提交。

workspace 另外验证从真实终端触发快捷键、不发送控制字节、输入法组合期间不接管及终端节点保留。

相关既有用例为 workspace、session-restore、reading-workspace、document-search、search-navigation、i18n 和 document-performance（small）。功能开发阶段运行 lint、typecheck、build 及这些定向用例；v0.1.12 发布另运行完整 verify 和打包后的实际 EXE 检查。
