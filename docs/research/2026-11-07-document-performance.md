## 原因与修复

目录曾直接写入标题 DOM ID，Milkdown 又根据自己的文档模型同步另一种 ID。带编号和标点的标题因此无法定位；编辑时的批量属性变更也触发额外解析和布局。目录现在从 ProseMirror 模型读取标题位置，缓存对应 DOM 节点，兼容目录别名和原生 ID。滚动时二分查找当前位置，不再逐帧扫描全文。

代码块离开视口后，库会销毁 CodeMirror 并换成源码占位块。最小复现中高度从 129 px 降到 86.5 px，改变了正文滚动位置。新增适配层记录已渲染高度，在占位和图表加载阶段保留空间；重新显示或编辑代码时继续按实际内容布局。CodeMirror 活动行不再使用单独底色，深浅主题下首行与其他行一致。

Mermaid 的 SVG 布局和清理曾占用工作台渲染线程。现在由独立隐藏 BrowserWindow 执行，启用 sandbox、关闭 Node 集成，不加载工作台 preload；独立 session 和 CSP 限制网络及导航。主进程校验请求来源、文本长度，串行执行并缓存完成结果，限制 24 个待处理任务、32 个缓存项和 8 MB 缓存。切到其他文件或源码时取消旧任务并关闭图表进程，保留完成的缓存；关闭工作台清理全部资源。真实渲染失败仍显示错误，取消不会覆盖新内容。

HTML 沿用原文和 sandbox 预览路径，切换时不会继续等待旧 Markdown 的图表计算。课程引用的本机字体文件不存在，浏览器会加载原文声明的 CDN 字体；字体请求本轮约需 1 秒，首次内容绘制已经提前完成。额外字体实验确认默认字体策略没有等下载完成才绘制，因此没有改写原文、替换字体或注入字体策略。
